# GameEval Studio 操作指南

日期：2026-10-13 · 版本：1.0

## 1. 启动与首次使用

在 PowerShell 进入目录：

```powershell
cd Tools/game-eval-studio
npm ci --registry=https://registry.npmjs.org
npm run dev
```

从仓库根目录执行以上命令，需要 Node.js 22.12+。已经安装依赖时直接 `npm run dev`。打开 `http://127.0.0.1:5173/`；结束使用后在终端按 Ctrl+C 停止服务。不要双击 `index.html` 启动，ES module 和哈希导出需要正常的 HTTP 本地服务。

首次进入显示“GPU 地形的 LOD 连续性”示例。它是模板参考，不是项目里真实存在的可运行评测题；基线、场景和设备必须替换。首版以 Unity 为默认，可在任务设定中改成 Godot、Unreal、Web 或其他引擎。

## 2. 新建任务

1. 点击左侧“新建评测任务”。
2. 选择玩法逻辑、图形与地形、战斗与 AI、游戏 UI、性能优化或完整小游戏。
3. 填写名称、简述与难度，点击“从模板起草”。
4. 在“任务设定”填写真实的仓库 URL + commit SHA 或归档标识、引擎版本、入口/场景、评测设备。
5. 调整随机种子、时间预算、通过阈值、运行协议、允许工具和联网范围、资产约束与交付物。

起草是本地模板操作，简述不会被 AI 自动拆解。模板提供可编辑候选需求和标准；专家必须按实际任务修改。修改“领域”或“难度”只改变元信息，不会替换已有条目，避免编辑结果被覆盖。

难度在新建时决定默认时间预算：基础 60 分钟、进阶 120 分钟、专家 240 分钟。已有任务的时间预算可单独修改。

## 3. 编辑需求列表

点击条目展开，每条包含稳定 ID、名称、优先级、所属领域、开发描述、观察步骤和验收条件。

推荐顺序：先写开发结果，再写专家实际会执行的操作，最后写可观察的验收。例如“在固定输入序列中运行 5 秒，比较 30/60/120 FPS 位移，偏差不超过 5%”，比“移动流畅”更可评判。

用“添加需求”增加条目，用条目底部“删除需求”移除。有关联规则时删除会提示影响；删除后规则保留，右侧会提示悬空关联，需在“评测规则”中修复。系统不会将悬空规则自动绑定到新需求。

P0/P1/P2 表示需求优先级，不自动决定规则权重或硬门槛。P0 是否必须通过，应由专家在规则中明确设置。

## 4. 编制评测规则

每条规则至少关联一条需求，并填写评分维度、方法、权重、证据要求和 0–4 分锚点。全部需求都需有规则覆盖，全部规则的权重合计必须为 100，每条权重大于 0。

评测方法的含义：

| 方法 | 专家使用场景 |
| --- | --- |
| 静态检查 | diff、场景结构、依赖、资源生命周期、交付说明 |
| 自动化运行 | 构建、状态机、输入回放、行为断言 |
| 性能采样 | 同设备、同负载、预热后采样，报告采样口径 |
| 视觉检查 | 固定相机路径、分辨率和参考条件下检查画面 |
| 专家试玩 | 焦点、控制反馈、边界行为与完整游戏循环 |

这些只是规则描述，不会在应用中启动引擎。实际执行与证据采集由专家或外部运行器完成。

评分：0 未实现；1 核心失败；2 部分达标；3 完整达标；4 在明确的重复/边界验证中稳定达标。模板描述应按实际题目细化，不要把额外无关功能写成加分条件。

“硬门槛”至少 3 分才通过，低于 3 分压过总分。每题至少保留一条“可运行性”门槛。公开范围默认“私有”；设为公开后该规则会进入 agent 文件。私有规则只能细化已公开需求，不应追加秘密功能。

右侧“交付前检查”显示覆盖、权重、门槛和问题。点击问题可跳到对应设定或条目；超过四项时可展开全部问题。

## 5. 用专家试评校准规则

填写评审专家和匿名提交标识，例如 `expert-01`、`submission-014`。逐条选择 0–4 分，填写观察结果、证据引用与扣分原因。证据示例：

```text
playthrough.mp4 00:12–00:38：键盘可完成物品使用与关闭。
logs/inventory-run.json：三轮断言通过；关闭再开无重复订阅。
```

证据仅为文本引用，应用不上传附件，也不检查文件是否存在。请与实际运行资料一同保管。

总分为 `Σ(规则权重 × 评分 / 4)`。所有规则达到 3 分时为 75 分；达到 4 分时为 100 分。通过需同时满足：任务质量检查通过、专家与提交标识齐全、每条规则有分数与证据、所有门槛至少 3 分、总分达到任务阈值。

未评、缺证据或任务定义不完整时，显示“待完成”；临时分只统计已评分部分，不是正式总分。0 分是有效评分，不等于未评。

修改任务设定、需求或规则会清空当前试评，避免用旧标准的分数评价新标准。冻结版本不会因这些修改而变化。试评不是冻结的必需步骤，但建议对真实提交进行试评来发现标准歧义。

## 6. 冻结与交付

1. 在“版本与导出”修复全部质量问题。
2. 填写确认专家与评审说明，例如“已固定设备、校准边界轨迹与性能口径”。
3. 点击“冻结当前标准”，生成 v1 / v2 等独立快照。这只是在本地记录专家确认，不是身份认证或数字签名。
4. 在“导出版本”选择当前草稿或某个冻结版本。
5. 点击“下载完整 ZIP”；也可只下载任务提示或专家规则 JSON。

包结构：

```text
agent/
  task.md                 公开任务提示
  requirements.json       需求结构
  requirements.csv        含 BOM 的中文表格
  task.jsonl              不含私有规则的任务交换记录
expert/
  rubric.private.json     所有评分规则
  rules.csv               专家规则表格
  protocol.md             环境与评测协议
  evaluation.jsonl        完整的私有题目定义
  trial-review.json       仅草稿包包含当前试评
manifest.json             UTF-8 内容 SHA-256 校验和
README.md                 包使用说明
```

**只把 `agent/` 交给被测模型。** `expert/` 与 manifest 留在评测侧，整个 ZIP 不应放入 agent 可访问工作区。冻结版本不带当前草稿试评，防止不同标准混用。

版本页显示“当前草稿相对最新版本”的变更摘要。旧版本导出始终使用旧快照；修改草稿后需再次专家确认才产生新版本。

JSONL 是本工具自有交换格式，不是 Promptfoo、SWE-bench 或 Langfuse 的可直接运行配置。接入运行器时参考 `src/model.ts`，为每种规则方法实现执行与证据采集。

## 7. 题库整理与备份

- 左侧搜索按任务名称和领域筛选；点击任务切换。
- 同一标签刷新后恢复正在编辑的任务和页签。
- 标题右侧复制按钮创建新任务副本：保留定义，清空试评和版本。
- 删除任务会同时删除其本地版本，请先备份；操作需要确认。
- 左下“备份”下载全部任务、版本和当前试评的工作区 JSON。
- “导入”只接受本工具协议的工作区 JSON，最大 10 MB。导入为新任务，不覆盖已有题目；同一备份反复导入会产生副本。
- 单工作区最多 100 个任务、单任务 200 条需求 / 300 条规则 / 100 个版本，适合本地题目生产。大量题库建议分工作区备份管理。

数据属于当前浏览器的当前源，例如 `http://127.0.0.1:5173`。换浏览器、协议、主机名或端口都可能进入不同题库；不要混用 `localhost` 和 `127.0.0.1`。清理浏览器、切换隐私窗口或更换设备前，先下载备份。

## 8. 异常处理

| 现象 | 处理 |
| --- | --- |
| 冻结按钮禁用 | 查看右侧质量问题，补全确认专家和评审说明。 |
| 临时分很高但“待完成” | 检查漏评、证据、专家、匿名提交标识和题目质量。 |
| 总分达标但不通过 | 检查是否有硬门槛低于 3 分。 |
| 本地存储容量不足 | 当前数据保留在内存，立即下载备份；整理历史任务/版本或换浏览器。不能把“保存需要处理”当作已保存。 |
| 其他标签修改题库 | 自动保存暂停；先备份本标签数据，再点击“载入最新数据”。若确需用本标签覆盖存储，备份双方后确认“用当前题库继续保存”。 |
| 本地存储损坏 | 原数据不会覆盖。先“下载原始存储”，再导入正常备份；恢复界面上可确认使用当前题库继续保存。 |
| 导入失败 | 确认是工作区备份 JSON，而非 ZIP、单条 rubric 或 JSONL；应用拒绝不符合结构的数据。 |
| 5173 端口被占用 | 关闭原有服务，或有意识地改用新端口并导入备份；应用不会自行跳端口。 |

## 9. 复现验证

```powershell
npm test
npm run build
```

浏览器测试需要 Python Playwright，安装方式见根目录 README。另开终端保持应用运行，执行：

```powershell
python tests/e2e.py --url http://127.0.0.1:5173/
```

测试使用独立浏览器上下文，生成模拟题库和示例证据，不代表测试过实际游戏实现。
