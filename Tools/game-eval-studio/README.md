# GameEval Studio

面向游戏开发专家的中文评测内容工作台，为 coding agent 编写需求列表和评测规则，形成可复现、可解释、可交付的评测题目。

使用本地确定性模板起草，支持完整编辑流程。数据保存在当前浏览器，不需要 API key；实际模型运行、游戏启动与性能采集由外部执行器或专家完成。

## 快速启动

需要 Node.js **22.12+** 和 npm。在仓库根目录执行：

```powershell
cd Tools/game-eval-studio
npm ci --registry=https://registry.npmjs.org
npm run dev
```

打开 [本地工作台](http://127.0.0.1:5173/)。依赖安装后再次使用只需 `npm run dev`；Ctrl+C 停止服务。请通过 HTTP 服务访问，不要双击 `index.html`。

默认固定 loopback 地址和 5173 端口，端口被占用会报错，不会静默切换。更换浏览器、主机名或端口会进入另一份存储，先下载工作区备份。

生产构建与本地预览：

```powershell
npm run build
npm run preview
```

## 建议使用流程

1. **从模板起草：**选择玩法逻辑、图形与地形、战斗与 AI、游戏 UI、性能优化或完整小游戏，填写名称、简述与难度。简述作为背景保留，模板不会自动理解和拆解任意自然语言。
2. **固定任务环境：**填写真实引擎版本、仓库 URL + commit SHA 或归档标识、场景/入口、设备、seed、时间预算、运行协议和工具/网络/资产约束。首次示例中的占位信息必须替换。
3. **编制需求与规则：**每条需求写清开发内容、观察步骤、验收条件；每条规则关联需求，设置维度、方法、权重、证据和 0–4 分锚点。
4. **专家试评：**对外部实际运行结果录入匿名提交编号、评审人、逐条分数与证据引用，检查标准是否有歧义。
5. **冻结并交付：**右侧质量检查全部通过后，填写确认专家和评审说明，冻结版本并下载 ZIP。草稿也可导出用于讨论。

修改任务定义会清空当前试评；冻结快照不受后续修改影响。刷新会恢复当前标签正在编辑的任务和页签。搜索、复制、取消删除与确认删除均可在界面完成；复制保留题目定义，清空版本与试评。

## 功能与评测约束

| 功能 | 行为 |
| --- | --- |
| 六类模板 | 每类起草 5 条需求与 5 条规则，包括构建/运行门槛，专家可自由增删编辑。 |
| 需求列表 | 稳定 ID、优先级、领域、描述、观察步骤和验收条件。 |
| 规则集 | 多需求关联、维度、观察方法、权重、五级锚点、证据要求、公开范围与硬门槛。 |
| 质量检查 | 检查环境、字段、ID、悬空关联、需求覆盖、权重合计和可运行性门槛；问题可点击定位。 |
| 专家试评 | 匿名提交与专家身份说明；逐项分数和证据；区分临时分与正式结论。 |
| 版本管理 | 冻结独立快照、记录专家确认、查看草稿差异、导出指定版本；新条目不复用历史版本 ID。 |
| 数据管理 | 自动保存、离开页面前补写、JSON 备份、严格校验后导入为新任务。 |
| 响应式界面 | 桌面与窄屏操作；原生对话框焦点管理、键盘可用、减少动效。 |

权重总和必须为 100，每条权重大于 0，每条需求至少有规则覆盖，至少一条可运行性硬门槛。删除被引用需求后需修复悬空规则。

评分计算：

```text
总分 = Σ(规则权重 × 原始评分 / 4)
硬门槛：至少 3 分
通过：全部评分与证据完整 + 门槛通过 + 总分达到任务阈值
```

0 分是已评的失败，未评不能视作零分。有分数但缺证据、缺评审人/提交标识、题目质量不完整时仍为“待完成”。每条规则达到 3 分时总分 75，达到 4 分时总分 100。此工具使用 0–4 协议；仓库现有三模型地形报告的 0–5 评分保持独立，不自动换算。

证据字段保存录屏时间段、日志路径和观察说明等文本，不上传附件，也不核实引用文件是否存在。专家应校准模板阈值和题目语义，不应把结构检查通过当作内容已经正确。

## 导出与私有规则隔离

完整 ZIP 是专家交付包，**只将 `agent/` 提供给被测模型**。不要将整个包放入模型可访问的目录。

```text
agent/
  task.md                  公开任务提示与显式公开规则
  requirements.json / csv  需求列表
  task.jsonl               公开任务交换记录
expert/
  rubric.private.json      全部评分规则
  rules.csv                专家规则表
  protocol.md              专家评测协议
  evaluation.jsonl         完整私有题目定义
  trial-review.json        当前试评，仅草稿包包含
manifest.json              UTF-8 文件 SHA-256 校验和
README.md                  包使用说明
```

冻结版本只读取对应快照，不附带当前草稿试评。CSV 有中文 UTF-8 BOM、引号/换行转义与公式前缀处理。JSONL 为本工具自有协议，接入 Promptfoo、Langfuse、SWE-bench 或引擎运行器需要适配。

## 数据保存与恢复

题库按浏览器源存储在 localStorage；标签内编辑位置保存在 sessionStorage。左下“备份”下载全部任务、版本与试评的工作区 JSON；“导入”校验后分配新 ID 并合并，不覆盖已有任务。同一备份多次导入会生成副本。

**工作区备份 JSON 才能恢复题库，评测 ZIP 不是题库备份。** 清理浏览器数据、切换设备或使用隐私窗口前先备份。

| 状态 | 处理 |
| --- | --- |
| 权重/覆盖/环境不完整 | 点击右侧问题修复，不能冻结正式版本。 |
| 存储容量不足 | 显示保存失败，内存改动仍可备份；立即下载备份再整理题库。 |
| 其他标签修改数据 | 自动保存暂停；备份本标签改动，再载入最新数据。需覆盖时由用户明确确认。 |
| 存储损坏 | 原始内容不覆盖，可下载原始存储，再导入有效备份。 |
| 浏览器拒绝读取存储 | 显示恢复失败说明，仍可备份内存题库；检查浏览器存储设置。 |
| 导入失败 | 检查是否为本工具的工作区 JSON，是否超过 10 MB，不能用单条 rubric 或 ZIP 回导。 |

容量上限：100 个任务；每任务 200 条需求、300 条规则、100 个版本；备份导入最大 10 MB。浏览器实际配额可能更小，以保存状态为准。首版没有多人账号、服务端数据库或云端备份。

## 可用性验证

2026-10-13 在 Windows、Node 22.20.0 和真实 Chromium 上复核：

- 官方 registry 全新 `npm ci` 成功，audit 为 0 漏洞。
- **30 项领域测试通过**：模板、质量约束、评分门槛、证据、版本历史 ID、备份协议、私有隔离和 SHA-256。
- **18 项浏览器流程检查通过**：新建/编辑/刷新、搜索/复制/删除、编辑位置恢复、试评、冻结、真实下载、备份回导、多标签冲突及存储异常。
- TypeScript 检查与生产构建通过；浏览器检查针对 `npm run preview` 提供的生产产物。
- 五个页面在 375 / 768 / 1024 / 1440 宽度下无文档横向溢出；对话框 Esc、焦点恢复和减少动效通过；主流程无未处理 JavaScript/控制台错误。

这些验证覆盖本地题目生产流程；没有在此 App 内运行游戏或评估真实模型，也不能替代专家对题目内容的审核。

复现命令：

```powershell
npm test
npm run build
```

真实浏览器测试需要 Python 3 和 Playwright。一个终端运行 `npm run preview`，另一个终端在 App 目录执行：

```powershell
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python tests/e2e.py --url http://127.0.0.1:5173/
```

测试使用独立浏览器上下文，不修改日常浏览器题库。截图、下载 ZIP、备份及 `e2e-report.json` 位于已忽略的 `test-results/`。`node_modules/` 和 `dist/` 同样不提交。
